# CONDITIONS_n_CONSTRAINTS

## Why this file exists

This file shows the bounds within which the project is actually carried out.

## What belongs here

- constraints on time, resources, and dependencies;
- risks and external conditions;
- mandatory conditions that affect planning.

## What does not belong here

- the project's target state;
- canonical reference facts with no tie to constraints;
- current execution steps instead of `PLAN.md`.

---

## Example

> For the project “Publishing a training course on workspace structure”

**Resources:**
- Materials author — 1 person; reviewer — the program curator (part-time).
- Tools: a markdown editor, public git hosting, an LLM assistant.

**Deadlines:**
- Structure draft — by May 10, 2026.
- Public announcement — not before reviewer approval.

**Constraints:**
- Public files must not include internal machine paths or students' personal data.
- Cover-design budget is fixed; do not plan spend above the limit.

**Dependencies:**
- The course launch depends on the ruleset in a neighboring public repository being ready.

**Risks:**
- A one-week slip in review slips the announcement; there is no backup reviewer.
