# DECISION_LOG

**Optional slot.** The file is in the skeleton so its location is predictable. Keep a live log if this folder regularly records choices that set standards. If it does not, you may skip copying the file when you instantiate the template.

## Why this file exists

This is the folder's decision log. Record matters that the owner could have decided differently and whose outcome remains in force as a standard.

## What belongs here

- a choice between alternatives: “selected A, rejected B; record the resulting value in FACTS”;
- a standard that remains in force until a new decision changes it;
- a link to where the current outcome is recorded, usually `FACTS.md`.

Write choices in the past tense—“selected” (выбрали), “rejected” (отклонили), “the standard is …” (норма такая-то)—rather than describing work performed.

## What does not belong here

Work such as “file was created,” “moved to archive,” or “check was completed.” That belongs in the work log (`WORK_LOG.md`).

Stop list of verbs and phrases for this file: created (создан), created (создано), moved (перенесено), extracted (вынесен), completed (выполнено), check completed (проверка выполнена), update completed (актуализация выполнена).

## Before you write an entry

Ask two questions:

1. Could the owner have chosen differently, and does the outcome remain in force as a standard?
2. Does the event have a responsible person and an artifact, such as a file, check, or transfer?

Only the first answer is “yes” — record it only in `DECISION_LOG.md`.
Only the second answer is “yes” — record it only in `WORK_LOG.md`.
Both answers are “yes” — write two distinct entries, not the same paragraph in both files.

## Example

> For an `NN_groundwork` folder in a training workspace

**August 2, 2026.** The “canon stays with the domain; groundwork holds the catalog and indexes” model was selected; copying how-to guides into this folder was rejected. Record in FACTS: domain canon remains with its owner.
