# WORK_LOG

**Optional slot.** The file is in the skeleton so its location is predictable. Keep a live log if this folder regularly records work that has a responsible person and an artifact. If it does not, you may skip copying the file when you instantiate the template.

## Why this file exists

This is the folder's work log. Record items that have both a responsible person and an artifact here.

## What belongs here

- “file X was created”;
- “the tag was checked against the CHANGELOG”;
- when a decision has already been made: “the standard from the DECISION_LOG dated [date] was recorded in FACTS.”

Write the action completed and its artifact, not the wording used to choose a standard.

## What does not belong here

Decisions such as “approved,” “decided,” or “adopted.” Those belong in the decision log (`DECISION_LOG.md`).

Stop list of verbs and phrases for this file: approved (утверждено), decided (решено), adopted (принято).

## Before you write an entry

Ask two questions:

1. Could the owner have chosen differently, and does the outcome remain in force as a standard?
2. Does the event have a responsible person and an artifact, such as a file, check, or transfer?

Only the first answer is “yes” — record it only in `DECISION_LOG.md`.
Only the second answer is “yes” — record it only in `WORK_LOG.md`.
Both answers are “yes” — write two distinct entries, not the same paragraph in both files.
