# CONDITIONS_n_CONSTRAINTS

## Зачем нужен файл

Этот файл показывает рамки, в которых проект реально выполняется.

## Что сюда класть

- ограничения по времени, ресурсам и зависимостям;
- риски и внешние условия;
- обязательные условия, которые влияют на планирование.

## Чего сюда не класть

- целевое состояние проекта;
- канонические справочные факты без привязки к ограничениям;
- текущие шаги выполнения вместо `PLAN.md`.

---

## Пример

> Для проекта «Публикация обучающего курса по структуре workspace»

**Ресурсы:**
- Автор материалов — 1 человек; рецензент — куратор программы (неполный день).
- Инструменты: markdown-редактор, публичный git-хостинг, LLM-ассистент.

**Сроки:**
- Черновик структуры — до 10 мая 2026.
- Публичный анонс — не раньше утверждения рецензентом.

**Ограничения:**
- В публичных файлах нельзя указывать внутренние пути машины и персональные данные учеников.
- Бюджет на дизайн обложки — фиксированный; сверх лимита не закладывать.

**Зависимости:**
- Выход курса связан с готовностью набора правил в соседнем публичном репозитории.

**Риски:**
- Сдвиг рецензии на неделю сдвигает анонс; запасного рецензента нет.
