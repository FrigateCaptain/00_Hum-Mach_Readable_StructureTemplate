# GOALS

## Зачем нужен файл

Этот файл фиксирует целевое состояние проекта и критерии его успешности.

## Что сюда класть

- главную цель;
- подцели и ожидаемые результаты;
- критерии успешного достижения и при необходимости anti-goals.

## Чего сюда не класть

- детальную последовательность задач;
- устойчивые факты и настройки;
- случайные идеи на будущее без связи с целевым состоянием.

---

## Пример (ИИ / workspace)

> Для проекта «Публикация обучающего курса по структуре workspace»

**Главная цель:** добиться, чтобы шаблоном активно пользовались — скачивали, применяли в своих workspace и делились им с коллегами.

**Подцели:**
- репозиторий опубликован, README и STRUCTURE_GUIDE прошли рецензионный просмотр.

**Критерии успешного достижения:**
- участники курса могут самостоятельно форкнуть и адаптировать шаблон;
- LLM-ассистент находит нужные документы без дополнительных подсказок.

**Anti-goals:** не создавать SaaS-инструмент, не поддерживать Notion-версию.

## Пример (другая область)

> Для проекта «Переезд офиса компании в новый бизнес-центр»

**Главная цель:** перевести команду из 80 человек в новый офис без потерь рабочего времени и без срыва клиентских обязательств.

**Подцели:**
- новый офис подготовлен к въезду: рабочие места, переговорные, инфраструктура, доступы;
- команда переехала и работает в новом офисе;
- старый офис закрыт, обязательства перед арендодателем исполнены.

**Критерии успешного достижения:**
- ни один клиентский дедлайн не сорван в окно переезда (±2 рабочих дня);
- все сотрудники имеют рабочее место и доступ к системам в первый рабочий день в новом офисе;
- бюджет переезда уложился в утверждённый коридор (отклонение < 10%);
- удовлетворённость сотрудников новым офисом (опрос через 2 недели) — не ниже 7/10.

**Anti-goals:** не использовать переезд как повод для пересмотра состава команды; не менять без необходимости мебель или технику одновременно с переездом — это два разных проекта.
