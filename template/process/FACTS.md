# FACTS

## Зачем нужен файл

Этот файл хранит устойчивые настройки и правила, на которые опирается процесс.

## Что сюда класть

- подтверждённые ссылки, параметры, роли и договорённости;
- стабильные условия запуска;
- канонические определения используемых сущностей.

## Чего сюда не класть

- временные решения, которые ещё не подтверждены;
- историю изменений вместо фактов;
- детальные шаги выполнения вместо `workflows/`;
- журнал выбора нормы: «выбрали A, отклонили B» — в `DECISION_LOG.md`; сюда — актуальное значение после решения.

---

## Пример

> Для процесса «Управление правилами AI-ассистента»

**Расположение правил:**
- Cursor-правила: `~/.cursor/rules/` (`.mdc`-файлы).
- Базовые правила из публичного репозитория: `https://github.com/your-username/llm-rules-base`.

**Роли в процессе:**
- Владелец: Иван К. — единственный, кто может одобрить перевод правила из черновика в основной набор.

**Условия запуска:**
- Плановый ревью всего набора правил — раз в месяц, первый понедельник.
- Внеплановый ревью — при появлении сбоев поведения AI.

**Категории правил (принятая классификация):**
- `always` — применяются ко всем файлам всегда.
- `auto-attached` — применяются к файлам по glob-паттерну.
- `agent-requestable` — только по запросу агента.
