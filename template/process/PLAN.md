# PLAN

## Зачем нужен файл

Этот файл фиксирует улучшения процесса, ближайшие действия и текущий рабочий фокус.

## Что сюда класть

- этапы внедрения или улучшения процесса;
- статусы задач;
- следующий шаг по развитию процесса.

## Чего сюда не класть

- постоянные операционные инструкции;
- канонические факты и параметры;
- backlog-темы без решения об их приоритете;
- журнал сделанного: работы по корректировке процесса — в `WORK_LOG.md`; исполнение цикла — в `CYCLE_LOG.md`, если слот заведён.

---

## Пример

> Для процесса «Управление правилами AI-ассистента»

**Итерация 1 — Базовая структура** ✅ завершена (апрель 2026)
- [x] Описаны категории правил и их приоритеты.
- [x] Написан workflow для добавления нового правила.

**Итерация 2 — Автоматизация проверки** 🔄 в работе
- [ ] Добавить хук pre-commit для валидации синтаксиса `.mdc`.
- [ ] Написать workflow для периодического ревью всего набора правил.

**Текущий фокус:** подготовить workflow ревью правил до конца апреля 2026.

**Следующий шаг:** согласовать с командой критерии устаревших правил.
