# VERSION_LOG

**Опциональный слот.** Заводить, когда у процесса или у системы, которая его обслуживает, есть внутренние версии. Имя файла можно выбрать при установке; в шаблоне показано каноническое имя слота.

## Зачем нужен файл

Журнал **внутренних** версий процесса и/или системы, обслуживающей процесс.

## Что сюда класть

- номер или метку внутренней версии;
- что изменилось в логике или в обслуживающей системе относительно предыдущей внутренней версии;
- ссылку на решение в `DECISION_LOG.md`, если версия следует из выбранной нормы.

## Чего сюда не класть

- внешние релизы для пользователей (`RELEASE_LOG.md`);
- исполнение очередного цикла без смены версии (`CYCLE_LOG.md`);
- работы по правке файлов без смены версии (`WORK_LOG.md`).

---

## Пример

> Для процесса «Управление правилами AI-ассистента»

**Внутренняя версия классификации 0.3.** Категории правил: `always` / `auto-attached` / `agent-requestable`. Это версия схемы внутри процесса, не публичный выпуск набора правил.
