# CONTEXT

## Зачем нужен файл

Этот файл объясняет, почему процесс существует и в каком операционном контуре он выполняется.

## Что сюда класть

- источник потребности в процессе;
- участников, роли и внешние зависимости;
- договорённости, которые объясняют текущую схему работы.

## Чего сюда не класть

- стабильные справочные параметры без контекста;
- список шагов процесса вместо `workflows/`;
- цели продуктового уровня, если папка уже стала проектом.

---

## Пример

> Для процесса «Управление правилами AI-ассистента»

Процесс появился, когда правила LLM (`.cursor/rules/`) стали меняться часто и без согласования — изменение в одном месте ломало поведение в другом. Нужен был операционный контур для систематического обновления.

Участники:
- **Владелец процесса:** Иван К. (инициирует изменения, финальная верификация).
- **AI-ассистент:** выполняет изменения в файлах по инструкции из workflow.
- **Зависимость:** репозиторий `llm-rules-base` — внешний источник базовых правил.

Договорённости:
- Изменения в правилах фиксируются в `SERVICE_CHANGES_LOG.md` того проекта, которого касаются.
- Экспериментальные правила живут в `BACKLOG.md` до верификации, не в основном наборе.
